Overview

This page describes the entity-relationship (ER) model for artworks. The model for artworks shown in an exhibition builds on it and is described in Item in Exhibition Data Model.

The single source of truth is wikibase-model.json. The tables below are generated from it, and the same file drives the creation of Wikibase properties and class items (see catalogues/wikibase-artwork-load.ipynb).

Note

The field list is provisional (version 0.1). Properties are mapped to four schemas: Wikidata, CIDOC CRM 7.1.3, Linked Art and LIDO. Iconclass and AAT are used as controlled vocabularies for subjects and terms.

ER Diagram

The authoritative artwork source is the attached CSV artifact and its field names are the ones used below. Multi-valued fields, where present, follow the same ;-separated pattern used in the source data.

Exhibited at is represented on the exhibition-item relationship rather than as a direct attribute of the artwork entity, even though the import CSV still contains the column for catalogue loading.

Dimensions

Height, width and depth are stored as Wikibase quantity values in centimetres. The unit is a local item “centimetre” created by the load notebook, which links to Wikidata unit Q174728 through the equivalent-property mechanism.

CSV source fields

The source schema for artworks is the field list already used in the attached artwork.csv:

Field Required Notes
Instance of (main) Yes main class, usually work of art
Object type (type of artwork) Yes the narrower object type
Title Yes artwork title
Creator Yes creator item
Inception Yes creation date
Main Subject No subject or motif
Materials Yes material terms
Inventory Number No museum/collection id
Catalog Code No catalogue code
Width Yes dimension
Height Yes dimension
Depth No dimension
Part of Series No series membership
Depicts No depicted subject
Image No image URL
Exhibited at Yes exhibition item
Current Owner No current owner or keeper
Commons category No Commons category link

Rules:

  • These column names are now the authoritative field list for the artwork data model.
  • The internal *_id and term.csv layer remains available as a loading convenience, but the source CSV is the governing schema.
  • Dates may be YYYY, YYYY-MM or YYYY-MM-DD; a range such as 1997-98 is loaded with its start year and a warning.
  • Title is loaded as monolingual text with language code mul.
