Overview

This page describes all entities of the Linked Open Exhibition model in one place:

Section Entity CSV template
Artwork artwork (with its terms: material, object type, place) import/artwork.csv, import/term.csv
Item in Exhibition the Exhibited at statement of an artwork import/exhibition-item.csv
Exhibition exhibition import/exhibition.csv
Artist person (artist, author) import/person.csv
Catalogue exhibition catalogue (book), publisher import/catalogue.csv, import/scan-location.csv

The single source of truth is wikibase-model.json. The class and property tables on this page are generated from it, and the same file drives the creation of Wikibase properties and class items (see catalogues/wikibase-artwork-load.ipynb). The CSV-to-property tables describe what the load notebook does with each template column.

Note

The field list is provisional (version 0.1). Properties are mapped to four schemas: Wikidata, CIDOC CRM 7.1.3, Linked Art and LIDO. Iconclass and AAT are used as controlled vocabularies for subjects and terms. The earlier Wikibase4Research column is no longer part of the model.

ER Diagram

EXHIBITED_AT and APPEARS_IN are not items of their own. They are statements on the artwork whose value is the exhibition or catalogue, with the other columns as qualifiers. Multi-valued fields in the CSV files use ; as separator.

Dimensions

Height, width and depth are stored as Wikibase quantity values in centimetres. The unit is a local item “centimetre” created by the load notebook, which links to Wikidata unit Q174728 through the equivalent-property mechanism.

Item in Exhibition

An artwork is linked to an exhibition with an Exhibited at statement on the artwork. The details that only the exhibition catalogue knows (catalogue number, catalogue page, the title as printed, a note) are added to that statement as qualifiers. There is no separate exhibition item. The model is the association between the Artwork and Exhibition models.

Why qualifiers instead of a separate item?

The catalogue details belong to one artwork in one exhibition. Qualifiers on the Exhibited at statement keep them next to the statement, work for artworks that appear in several exhibitions (one statement per exhibition), and follow the usual Wikidata pattern for exhibition history (P608).

Which catalogue an artwork appears in, and where

Each artwork records the catalogue it appears in with an Appears in catalogue statement. For the Baldessari artworks this is CAT001, because that is the catalogue the records were taken from. The statements come from import/scan-location.csv, one row per artwork and catalogue (and per page, once pages are known). The columns after catalogue_id are optional. When they are filled in, they let a reviewer check the extraction against the scan. An artwork on several pages has several rows. The loader turns each row into a statement on the artwork (pointing to the catalogue item) with the other columns as qualifiers.

Region format. scan_region uses the W3C Media Fragments syntax xywh=percent:x,y,width,height, for example xywh=percent:10,20,40,8. Percent values refer to the page size, so they stay valid for any image resolution. xywh=pixel:x,y,width,height is also accepted. The same syntax is used by IIIF and the Web Annotation model, so the regions can later be shown on a viewer without conversion. The corners from hOCR (bbox x0 y0 x1 y1) or ALTO (HPOS, VPOS, WIDTH, HEIGHT) have to be converted to x, y, width, height first.

The rows in scan-location.csv currently only link every artwork to CAT001. Pages, regions, extraction method and review status will be added when the extraction data (plan B) is ready.

Best practices for catalogue records

  1. Use Wikidata items: link to existing Wikidata items for authors and organizations to enable cross-institutional discovery.
  2. ISBN validation: ISBN-13 numbers must have a valid check digit. Use the format with hyphens (978-X-XXXX-XXXX-X) for readability.
  3. Publication dates: use ISO 8601 (YYYY-MM-DD) where precise dates are available, or just YYYY for year-only precision.
  4. Multilingual titles: where a catalogue is published in several languages, add further title statements as monolingual text.
  5. URL persistence: prefer persistent URLs (DOI or similar) over temporary web links for described_at_url.
